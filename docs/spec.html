1Vision & goals

Linux has capable download tools (aria2, wget, curl), but none pairs a strong engine with a polished desktop experience. ADM aims to be the Linux equivalent of IDM/FDM: it should saturate your connection, survive anything, and be pleasant to use.

⚡ Fast

Dynamic multi-connection segmentation keeps every connection busy until the last byte.

🛡 Resilient

Pause and resume survive crashes, reboots, network drops and expired links.

📦 Batch-native

Hundreds of files handled as one unit: import, filter, rename, track, and retry only the failures.

✨ Modern

A clean, animated, keyboard-friendly UI with live per-segment visualization and dark/light themes.

Non-goals for v1

  • Windows/macOS builds. The architecture allows them later, but they are not tested in v1.
  • BitTorrent, HLS/DASH video and site-specific extractors. These are planned for v2+.
  • Cloud sync or accounts.

3Architecture

The engine is a standalone Go package with no UI dependencies. The desktop app, the CLI and the browser bridge are thin clients of the same core service. Communication is event-driven: the engine publishes state and progress events, and the UI subscribes to them.

Repository layout

adm/
├── main.go, app.go          // Wails entry + bindings exposed to the frontend
├── internal/core/           // engine: manager, job, segment, batch, limiter
├── internal/store/          // SQLite persistence
├── internal/batch/          // URL pattern expansion, list parsing, rename templates
├── internal/probe/          // HEAD/range probing, filename detection
├── cmd/adm/                 // CLI companion (later)
└── frontend/                // Svelte + Tailwind UI

4Download engine

4.1 Job lifecycle

queued → probing → downloading ⇄ paused → verifying → completed, plus failed (retryable) and canceled. Every transition is persisted before it is announced, so the on-disk state is never behind the UI.

4.2 Probing

  • Send HEAD. If the server rejects it or gives no length, send GET with Range: bytes=0-0 and read Content-Range.
  • Record the size, Accept-Ranges, ETag, Last-Modified, content type and the final URL after redirects.
  • Filename priority: Content-Disposition (including RFC 5987 filename*), then the final URL path, then a name generated from the MIME type.

4.3 Dynamic segmentation

A file is split into N initial ranges (default 8, maximum 32). When a worker finishes its range, it steals work: it takes the active segment with the most bytes remaining and splits it in half. The original worker keeps the first half and the idle worker takes the second. Splitting stops below a minimum size (1 MiB). This avoids the "one slow tail segment" problem of static splitting.

type Segment struct {
    ID         int
    Start, End int64   // inclusive byte range; End may shrink when stolen from
    Done       int64   // bytes written from Start
}
// Workers write with os.File.WriteAt into one preallocated .part file,
// so no merge step is needed. Progress is checkpointed to SQLite every ~1 s.
  • If the server doesn't support ranges, fall back to a single connection with no resume, and warn the user.
  • On resume, compare ETag/Last-Modified/size. If any has changed, restart the download (and ask the user first).
  • Each worker has its own retry with exponential backoff and jitter. 429/503 responses respect Retry-After.
  • If a worker hits repeated connection errors, the job lowers its connection count (adaptive backoff).

4.4 Integrity & finalization

  • Optional checksum (MD5 / SHA-1 / SHA-256 / SHA-512) verified after completion.
  • Atomic finalize: file.part is fsynced, then renamed to file. The rename-on-conflict policy is applied here.

5Batch downloads

A batch is a named group of downloads managed as one unit. Every item in a batch is a normal job linked by batch_id, so segmentation, pause/resume and retry work unchanged. The batch only adds grouping, aggregate reporting, ordering and batch-level policies.

5.1 Ways to create a batch

SourceBehaviorPhase
Paste listMulti-line text. Extracts every URL, ignores junk, and removes duplicates.v1
Import file.txt (one per line), .csv (url, filename, folder), .json, .metalinkv1
Pattern / range URLimg[001-250].jpg (zero-padding kept), [a-z], stepped [0-100:5], several ranges in one URL. Shows a live preview and count.v1
Page link grabberFetches the HTML and extracts a[href], img, video, source. Filters by extension, regex, domain and size.v2
Directory listing"Index of /" and FTP folders with optional recursion, preserving the folder structurev2
Browser "download all"The extension sends the selected or all links as one batchv2
PlaylistsThrough the yt-dlp backendv3

5.2 Review dialog

  • Items table with a checkbox, URL, detected name, size, type icon and probe status. A bounded worker pool (default 8) probes in parallel and fills in rows live.
  • Filters: extension chips, min/max size, include/exclude regex, and "select all / invert".
  • Rename template with a live preview. Tokens: {name} {ext} {index} {index:03} {batch} {date} {host}.
  • Destination: a folder, an auto-created subfolder named after the batch, or the remote path structure kept.
  • Batch settings: order (parallel or sequential), max parallel items, connections per item, speed limit, queue, and start (now, paused, or scheduled).
  • Conflict policy: skip / overwrite / auto-rename / resume existing .part.

5.3 Running a batch

  • Appears as one expandable card with aggregate progress, combined speed, ETA and counters (37 / 120 done · 2 failed).
  • Group actions: pause, resume, cancel, set priority, change limit, retry failed only.
  • Per-item control still works inside the expanded view. Items can be reordered by dragging.
  • Failure policy: retry each item k times, then either continue with the others or stop the batch.
  • Per-host politeness: a cap on total connections to one host across the batch, to avoid bans.
  • Link refresh: re-import a list and match items by filename to swap in fresh signed URLs while keeping partial data.

5.4 After completion

  • One summary notification ("Season 1 — 12 files, 8.4 GB, 1 failed").
  • Batch post-actions: extract all, join split archives, verify against a SHA256SUMS file, run a script, sleep or shut down.
  • Export the failed URLs, or the whole batch, as .txt or .metalink. Saved batch templates hold reusable settings.

5.5 Concurrency model

Three nested limits: global active jobs ≥ batch max parallel items ≥ connections per job. On top of these sit per-host caps and three layers of token-bucket bandwidth limits (global → batch → job). The scheduler starts the highest-priority eligible job whenever a slot frees up.

6Queues, scheduling & limits

  • Multiple queues, each with its own concurrency, speed limit and schedule. A default "Main" queue is created on first run.
  • Scheduler: time windows (e.g. 02:00–07:00), weekday masks, and "stop when the window ends".
  • Profiles: Full speed, Balanced, Metered. Switchable from the tray or header in one click.
  • Bandwidth limit: global, per queue, per batch and per job. The limit can be changed live without restarting connections.

8Organization & automation

  • Auto-categories: Video, Music, Archives, Documents, Images, Programs, Other. Each has a default folder under ~/Downloads.
  • Rules engine v2: conditions (domain, extension, size, regex) → actions (folder, queue, connections, post-action).
  • Post-download actions: open, reveal in folder, extract, run script, mark executable.
  • History with full-text search, re-download, and duplicate warnings by URL or target path.

9UI / UX design

Design principles: calm by default, detailed on demand. The main list stays readable at a glance. The details drawer shows everything else. Motion is used only to communicate change (progress, reordering, state transitions), and honors prefers-reduced-motion.

Key UI elements

  • Sidebar: status filters, categories, queues and batches, each with live counts.
  • Header: a combined search / quick-add box (Ctrl K), a global speed sparkline and the profile switcher.
  • Download card: icon, name, meta line, percent, and a per-segment progress bar. Batch cards expand to show their items.
  • Details drawer: overview, segments map, HTTP headers, event log, checksum, and "copy as curl".
  • Dialogs: New download, New batch (with a Paste / Import / Pattern tabs), Settings.
  • Empty states with drop-zone illustrations; toasts for non-blocking feedback.
  • Multi-select with Shift/Ctrl, a right-click context menu, and full keyboard navigation.

10Data model

CREATE TABLE batches (
  id TEXT PRIMARY KEY, name TEXT, order_mode TEXT, max_parallel INT,
  on_failure TEXT, rename_tpl TEXT, dest_dir TEXT, created_at INT
);
CREATE TABLE jobs (
  id TEXT PRIMARY KEY, batch_id TEXT REFERENCES batches(id), queue TEXT,
  url TEXT, final_url TEXT, filename TEXT, dir TEXT, size INT,
  downloaded INT, status TEXT, error TEXT, etag TEXT, last_modified TEXT,
  resumable INT, connections INT, speed_limit INT, priority INT, position INT,
  headers_json TEXT, checksum TEXT, created_at INT, completed_at INT
);
CREATE TABLE segments (
  job_id TEXT REFERENCES jobs(id) ON DELETE CASCADE, idx INT,
  start INT, "end" INT, done INT, PRIMARY KEY(job_id, idx)
);

13Risks & open questions

  • WebKitGTK variance across distributions: target 4.1, and test on Ubuntu, Fedora and Arch. Flatpak removes most of this variance.
  • Servers that lie (wrong Content-Length, ranges ignored mid-stream): validate each response's Content-Range, and fall back to a single connection.
  • Aggressive multi-connection use may trigger rate limits or bans. Defaults are sensible, and per-host caps are included.
  • Browser extension packaging and store review take time. Deferred to v2.
  • Open: the final product name, and whether to support a headless daemon mode for servers in v1.
